# initx 设计决策

## 为什么以插件作为能力单元？

不同开发者工作流的演进速度和副作用不同。把能力放进插件，可以让宿主保持小巧，用户只安装自己需要并且理解的工作流。

## 为什么拆出 core 和 utils？

CLI 与插件需要共享行为，但共享行为应该只有一个宿主契约。`@initx-plugin/core` 与 `@initx-plugin/utils` 提供这个契约，插件不必复制工具或依赖私有 CLI 文件。

## 为什么提供 `ix`？

完整的 `initx` 适合文档和发现；`ix` 适合终端中反复输入。它只是别名，不是第二套实现。

## 为什么按需安装插件？

多数用户只需要部分工作流。按需安装可以缩小默认命令面，也能让能力的依赖和权限在安装时变得清晰。

## 为什么不是完整任务运行器？

构建图、项目内 pipeline 和依赖调度需要另一套执行模型。initx 优先解决可以脱离单个仓库独立安装的用户命令。

## 决策边界

所有插件都需要的行为属于宿主包；只为一个用户工作流存在的行为属于插件。这是主要架构不变量。
